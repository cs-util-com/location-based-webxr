# hud-status.ts

- **Purpose:** turn the REAL HUD scene output (the presenter's indicator meshes on the camera) plus the target list into the one-line DOM status. Deliberately reads presenter OUTPUT (children by name + visibility) instead of re-running placement math — the status line is then evidence of what the HUD actually shows, which is what the Playwright walk-flow spec asserts hysteresis against.
- **Public API:**
  - `summarizeHudScene(cameraChildren, cameraPosition, targets): HudSceneSummary` — counts visible `wayfinding-arrow` / `wayfinding-circle` children (labels/others ignored), `hidden = targets − arrows − rings` (floored at 0), `nearest` distance or null, and `indicatorStyle` (`"procedural" | "image" | "mixed" | null`) derived from the indicator children's object kind (`isSprite`), visibility-independent.
  - `formatHudStatus(summary)` — `` `targets 4 · arrows 3 · rings 1 · hidden 0 · nearest 19.2 m · procedural indicators` `` (dash when no targets; the style suffix drops out while `indicatorStyle` is null).
- **Invariants:** relies on the framework presenter's stable mesh names (`wayfinding-arrow`, `wayfinding-circle` — see the framework's `wayfinding-hud.ts.md`) and on sprite vs mesh being the only signal distinguishing the image-indicator path (the presenter names both identically); the label sprite never influences the style; pure, no three.js scene mutation.
- **Tests:** `hud-status.test.ts`.
- **Entrance readout ([HUD diamond entrance plan](../../../gps-plus-slam/GpsPlusSlamJs_Docs/docs/2026-09-05-2138-hud-diamond-entrance-animation-plan.md), M4):** `summarizeHudScene` takes the presenter's `entranceStats()` as an optional fourth input (`entrance` on the summary, `null` when not passed) — the one number that is NOT scene output, because redraw counts and their cost are not in the scene graph; `formatHudStatus` appends `· entrance N animating · R redraws · X.XX ms` only while an entrance animates or redrew in that frame, and `· last entrance T.TT ms · peak P.PP ms` for as long as any entrance has cost anything - the accumulated pair is the number read on the headset AFTER the entrance, so it must not vanish the frame after settling (PR #423 review). Under Playwright's fake clock every draw measures 0.00 and the pair is absent. That line is the owner's on-device cost read against the 11.1 ms frame budget at 90 Hz. Its millisecond figure is a per-frame `performance.now()` pair, clamped to 100 µs in a page that is not cross-origin isolated: on a desktop (~0.04 ms per redraw) it reads 0.00 or 0.10 and means nothing; on a headset (0.3-1.0 ms estimated) it is the number. `"mixed"` is no longer purely defensive: the framework's `circleEntrance` without `arrowSprite` produces it (the demo's derivation never does). Tests: `hud-status.test.ts` ("the entrance readout").
