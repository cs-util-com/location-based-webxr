Tour Viewer

Set up a tour that people open by scanning a printed code: host a zip, print the code, hang it, then measure it in AR and place content. Four steps, one at a time.

Start the tour

This tour runs in augmented reality on your phone. It needs the camera, to show the tour over what you see, and your location, to place it. Nothing is uploaded. Tap the button below; if the browser asks, allow both.

  1. 1 · Host your tour

    1. Get a tour zip: a recording from the Recorder app, or an empty one to start from.

    2. Upload it to Google Drive, Dropbox, GitHub or OneDrive and copy its share link. The printed code will point at this link, so keep the file where it is.

    3. Paste the link here and test it. A link that opens here is a link the printed code can carry.

  2. 2 · Print the code

    The code carries the link from step 1 - you are not asked for it again. Print it at 100% scale (no fit-to-page), and enter the printed side length so the AR setup can measure it.

    That is the address the code encodes: this page, carrying your tour link inside it. A long tour link means more squares in the code and smaller ones, which is harder for a phone to read. If the code will hang somewhere people scan it from a distance, put the tour link through a URL shortener, paste the short link in step 1, and test it there - the trade is one extra redirect for bigger, easier squares.

    Not every shortener works here. Some of them, bit.ly among them, let the link open when you tap it yourself but stop the tour loading for your visitors - so opening the short link in your own browser proves nothing. Step 1 is the test that counts: paste the short link there, wait for the tour to open, and only then print.

    Try this tour as a visitor on this phone

  3. 3 · Hang the code

    Fix the printed code where the tour starts: flat on a wall or a post, at about chest height, in a spot a phone can film squarely from a metre away. It stays there; visitors scan it to open the tour and again in AR to be placed exactly.

4 · Measure the code and place content

Stand at the hung code and start the AR setup. Hold the phone on the code until it is measured, then place text pins and photos where the tour should show them. Finish inside AR when you are done - the rebuilt zip appears here afterwards.

This device does not have the tour open yet. Paste the link from step 1 - on your phone, that usually means sending it to yourself.

AR opens the camera. Keep the printed code in view until the page says it is measured; walking a few metres with GPS reception lets the phone align to the map.

Last thing: upload this zip over the one from step 1, so the link - and with it the printed code - stays the same. Google Drive: on drive.google.com in a browser, right-click the file, "Manage versions", "Upload new version" (the Drive phone app cannot do this). Dropbox: upload the file with the same name into the same folder. GitHub: commit it over the same path. OneDrive: upload with the same name and choose "Replace".

You SHARED the zip rather than saving it, so it is now wherever that app put it - almost certainly as a NEW file with a new link, while the printed code still points at the old one. The instructions above are what fixes that, and they need the file: open the app you shared to, find the zip you just sent, and upload it over the step-1 file from there. On Google Drive "Manage versions" is only available in a browser, so that last step may have to wait for a computer.

Other settings

Opened tours are kept on this device (up to five, oldest dropped) so a revisit opens instantly and works offline. A changed file on the host is picked up automatically; clearing is only needed to free space.
