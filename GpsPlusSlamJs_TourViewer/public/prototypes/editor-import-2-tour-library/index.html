About this draft: the tour's own library

The idea. A file never goes straight into the world. It lands in the tour's library, a shelf in the bottom panel, wherever it was dropped. It is checked there, in plain view, and bad files wait there without stopping anything. Placing is a separate, second act: drag a good card onto the place or into a station.

  • One file, many uses. A card shows where it is used; hovering it lights those stations. Replacing a file changes every use at once, and a bad replacement is refused while the old one stays.
  • A drop on the place always has a station. Up to 60 m from a station it joins that station. Further away it starts a new one. The label under the pointer says which before you let go.
  • No error dialogs. A bad file is a card with a plain reason and what to do. A batch ends in one summary line.
  • The same file twice is noticed by its content and not added again; the same name with other content gets a number.

Real here. The checks read the actual bytes: file signature, cut-off files, outside references, decoder extensions, triangles, texture sizes and the model's real extent. Your own files go through the same checks and get a real thumbnail. No outside files and the 4096 x 4096 pixel cap are the tour's real rules.

Faked. "Make it lighter" does not change the bytes; it only shows the figures such a step would produce. fountain-scan.glb is a small model that claims to be 148 MB. The other limits (100 MB refused, 25 MB heavy, 800,000 triangles) are guesses for this draft. Placed items cannot be moved or turned here.

Weak spots. Two steps where one would do for a person who only wants one picture in one station. The shelf takes height away from the place on a small laptop. Whether unused files should stay in the tour file is open; here only used files count for what a visitor downloads.

The 3D view needs three.js from unpkg.com. Check the connection and reload.
