# .dependency-cruiser.cjs

## Purpose

[dependency-cruiser](https://github.com/sverweij/dependency-cruiser)
configuration for the Tour Viewer: the two universal structural rules, plus
its own import bans.

## Rules

- `not-to-unresolvable` (error) — fail on any import that cannot be resolved
  (catches path typos and missing files).
- `no-circular` (error) — fail on any circular dependency (the "component
  dependency loops" guard).
- `viewer-not-to-editor` (error) - the visitor page (`src/*.ts`) never
  imports the desktop editor (`src/editor/`), which loads Leaflet statically
  (M6 E1 plan review #5).
- `viewer-not-to-editor3d` (error) - the visitor's and the phone's pages
  (`src/*.ts`) never import the 3D editor (`src/editor3d/`), which brings
  the globe and the 3D tiles renderer. That no module outside
  `src/editor/` and `src/editor3d/` imports those PACKAGES (and the whole
  OSM package, `gps-plus-slam-osm`, its geoid table among it - a part of
  it is carved out only with a reason) is held by
  `src/editor-only-packages.test.ts`: this config reads only `src/`
  (`includeOnly`), so an import of a package is invisible to it. Both
  verified when added by probe files (`src/zz-probe.ts` importing
  `src/editor3d/probe.ts` and `gps-plus-slam-globe/editor`), each
  reported, then removed.
- `landing-not-to-editor` (error) - the creator's landing (`src/landing/`,
  the start page's first screen, loaded on every first visit) never
  imports either editor (`src/editor/`, `src/editor3d/`); the two rules
  above read only the top level of `src/`. Verified when added by a probe
  module (`src/landing/zz-probe.ts` importing `src/editor3d/` and
  `src/editor/`, both reported) and a probe test file (not reported), then
  removed.
- `viewer-not-to-kit-editor` (error) - the visitor's and the phone's pages
  (`src/*.ts`) and the landing (`src/landing/`) never import the editor
  kit's `chrome`, `scene` or `globe` (`../GpsPlusSlamJs_EditorKit/src/`);
  of the kit they may reach only its touch gestures (`src/touch/`). The
  same ban by specifier is in `src/editor-only-packages.test.ts`, and the
  bundle's in `src/editor3d-lazy.test.ts`. Verified when added by probe
  modules (`src/zz-probe.ts`, `src/landing/zz-probe.ts`, each importing
  `gps-plus-slam-editor-kit/chrome`, both reported) and a probe test file
  (not reported), then removed.
- `document-rules-through-tour-document` (error) - the shared rules of the
  tour a creator edits (`object-edits.ts`, `finish-rebuild.ts`,
  `tour-content.ts`, and `authoring-draft.ts` for `hostedObjects` and
  `applyObjectChanges` - the r875 milestone review #6; a rule is per
  module, so the draft's other rules are protected with them; and
  `code-book.ts` since the codes moved into the store, debug-captures
  plan M3a) are imported
  only by the tour document, the shared pure modules themselves and tests.
  The document's modules are named one by one, never by a pattern (a
  `tour-document-*` file is not exempt until it is listed): `tour-document.ts`
  (D29-D31), `tour-document-draft.ts` (the draft's follower) and
  `tour-document-save.ts` (the document's save, which does I/O - the
  rebuild, the photo bake - and reads the rules for its snapshot and its
  landing). A probe module `src/tour-document-probe.ts` importing
  `object-edits.ts` was reported, so the old `tour-document*` pattern's
  blanket exemption is gone. Every other importer is named in the rule with its reason:
  - permanent, read-only helpers: `viewer-placement.ts` (the visitor's photo
    spots), `creator-placement.ts` (the AR placement's world view);
  - permanent, the draft's own modules: `draft-persistence.ts` (its storage)
    and `editor/editor-draft.ts` (the desktop's draft store and its offer
    rules), and its peer `creator-draft.ts` (the phone's draft store; it
    reads the tour only through the document);
  - `editor/edit-main.ts` is NOT named: it reads the saved file's name
    through the session (`savedName()`), so the page imports none of the
    rules;
  - TEMPORARY: `creator-finish.ts` (the phone's Finish: its rebuild I/O),
    until it saves through the document's save too. The phone's tour
    itself is the document since its adoption (`creator-document.ts`),
    which removed `creator-settle.ts` and `creator-stations.ts` (it reads
    the document's `manifestToWrite`) and made `creator-draft.ts`
    permanent. Why the Finish is not on the save yet:
    `tour-document-save.ts.md` ("Not here yet").
  - Removed when the desktop's save became the document's thunk
    (`tour-document-save.ts`): `editor/editor-session.ts` (it saves
    through the thunk and shapes its edits by the document's
    `pinTextChange` / `objectMoveChange`) and `object-editing.ts` (the
    phone's pin text, through `pinTextChange`). The rule passes without
    them, and a probe import of `object-edits.ts` from `object-editing.ts`
    was reported again.
  - Verified when added by probe imports from `src/` and `src/editor/`,
    both reported; the `authoring-draft.ts` widening reported exactly its
    two unnamed importers (`draft-persistence.ts`, `editor/editor-draft.ts`)
    before they were named.
  - The TEMPORARY entries today: `creator-finish.ts`. No check fails on one that
    is no longer needed (declined in the review: an adoption removes its
    own line); this list is what to re-read after one.

## Resolving the editor kit

The kit is a workspace package whose `exports` point at TypeScript source.
With the cruiser's default resolve options its import read as
unresolvable and, being outside `includeOnly`, vanished from the graph
without a report - so a rule about it passed vacuously. The config
therefore sets `enhancedResolveOptions` (`exportsFields`, `conditionNames`,
`.ts` first) and anchors `includeOnly` to `^src/` plus the kit's
`^../GpsPlusSlamJs_EditorKit/src/`. The anchor keeps the other workspace
packages (now also resolved, the globe's source among them) out of the
graph; the one module the old unanchored `"src"` had matched besides the
app's own was Leaflet's `dist/leaflet-src.js`, a leaf with no rule about it.

## Usage

```bash
pnpm run check:boundaries   # depcruise -c config/.dependency-cruiser.cjs src
```

`check:cycles` (dpdm) additionally guards cycles from the `src/main.ts` entry;
the two tools overlap on circular detection by design (defence in depth).

## Tests

No unit test; exercised by the `check:boundaries` gate inside `pnpm test`.
