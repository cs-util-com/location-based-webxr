# maker-main.ts

**Purpose:** the wiring of `characters.html`: the library view and the six steps that make a character, built from the prototype `public/prototypes/character-library-1/maker.html`. The rules live in the modules it imports; this file connects them to the page.

## What it does

- **Library view:** lists the characters on this device (thumbnail, state, age) with Rename, Save as file (shared on a phone when the browser can, else downloaded) and Delete in an inline slot; the unfinished draft with Continue and Discard (with Undo); a line for interrupted saves with "Tidy up now"; "Import character..." with its refusals in words and a name question when the file carries none ("Waiting for a name..." on the button; leaving the library view settles it). The previews' animations are kept by canvas id (`createAnimSet`), so a re-cut replaces the talk-style ones. Reads the library again when the page becomes visible.
- **Shared with the editor:** the import flow (refusal card, name question) is `character-import.ts`, and the thumbnail crop and the age line are `character-thumb.ts`; the editor's Characters list uses both.
- **Steps:** describe; copy the prompt (when the browser refuses the clipboard, the text is selected for the author); make the picture; bring it back (file, paste button, page paste, drop); check (backdrops, "As drawn" preselected and "Steady body" one tap away, "Adjust the cut" folded, its sliders cutting again 220 ms after the last change); name and save; "Make another".
- **Cut:** in a module Worker through `createCutClient`; the phases show as they run; a newer request replaces an older one, whose `AbortError` ends only that cut. A new picture takes away the Undo of Start over or Discard (that Undo would put the old picture over the new one). A re-cut from the sliders whose cut was dropped meanwhile (Start over, Make another, Discard, before it began or while it ran) sets nothing and leaves its status line empty.
- **Save:** the chosen frames composed into the sheet and the first pose as `image.png`, through the library, which writes `character.json` last. The name and the description are read after the pictures are written, so a name typed meanwhile is the one saved; the talk style is read with the frames. The save belongs to the draft it was started from: it takes the store's `generation` first, saves nothing (and says so in a toast) when a new picture has started another draft by the time the pictures are written, and carries the generation on `saved`, which the reducer ignores for a replaced draft. While the save runs (`saveStarted` to `saveEnded` in the store), Start over and the library view's Discard are disabled (the Discard with the title "Discard waits until the character is saved" and "Saving..." in its row), so no Undo can bring back a draft the library saved without marking it; the library view is drawn again when the save ends. A new picture brought in while the library itself writes cannot be stopped: the character is saved, the new draft is not marked, and the toast says the character is in the library while the page goes on with the new one.
- **State:** the draft, the step and the cut status live in the Redux store of `maker-slice.ts` (`createMakerStore`); every change is a dispatch, and the page reads `makerStore.getState()` again after one. Renders are explicit calls, not a store subscription: a render rebuilds the step list and binds its listeners again, which a subscription would do on every keystroke in the description or the name. The box itself is safe either way, because `render()` writes the draft's description into it only when the two differ (so a new start, a Discard or an Undo never leaves stale text there, and the caret and an input method's composition are left alone while typing). The cost of explicit renders is that a place which changes the draft must remember to render. Beside the store stay the cut picture (`R`: canvases and pixel data; the store says `ready` exactly while it is set), the library promise, the greeting text, the re-cut timer, the talk-style render cache (`styleVersion`), the library view's generation guard (`homeSeq`), the thumbnail cache by library id (`thumbs`, an entry dropped on Delete) and the ids saved or imported in this page session (`justMade`, shown as "Just made" in the list).
- **Draft:** the store's listener keeps it in `localStorage` (`characters:maker-draft`; a write that fails, as in private mode, is ignored), and the store starts from it through `makerStateFrom`. The picture is not kept, so after a reload at the check or save step the page goes back to step 4 and asks for it again.
- `?in=editor` hides the "Tour editor" link and changes the lead; `?start=new` opens the steps.

## Async feedback

Every import, cut, copy, paste, save, rename, delete, tidy and file action shows an in-progress state (`busy`, or the cut phases) and ends in a toast or a visible final state; a failure goes to an error toast and the control comes back.

## Error reporting

The first statement after the imports is `startErrorReporting({ app: "tour-viewer", prod: import.meta.env.PROD })` (the framework's `utils/sentry-options.ts`): in a production build it starts the error service with the strict profile of the apps visitors use (errors only, no traces, an `app` tag, every report scrubbed of coordinates, map cells, long ids, quoted text and link paths). A dev server and the unit tests send nothing. The page flag `?sentry-test` sends one harmless test report. It runs after the imported modules have been evaluated, so an error thrown while a module loads is not reported.

## Tests

`playwright-tests/character-maker.spec.js` (the whole flow, the reload, the exchange file both ways, a cut failure, a JPEG refusal, a failed save, Discard and its Undo, a new picture ending the Undo offer, a re-cut landing after Start over, a second picture during the first cut's last moment, a name typed while the pictures are written, Discard waiting during a save (with its reason, over held library writes), a new picture during the picture writing (not saved) and during the library write (saved, an honest toast, and the new picture saved as a second character), Start over waiting during a save and back after a failed one, a new picture during a re-cut leaving no re-cut line, the layout at three viewports). The races use a slow worker answer, a slow PNG writer and a hook on each cut request switched on from the test (`slowSeams` in the spec), and held library writes (`holdWrites`). The modules it uses have their own unit tests; the page's rules are the reducers of `maker-slice.ts`.
