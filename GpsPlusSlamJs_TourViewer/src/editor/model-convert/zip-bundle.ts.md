# zip-bundle.ts

**Purpose:** a zip of a model's folder read into the files a conversion needs, and the list of the models a zip holds. `readZipBundle` runs in the converter's Worker, `listZipModels` on the page; tested in node.

## Public API

- `listZipModels(zip)`: the models of the zip by path, sorted as `readZipBundle` takes them (macOS and system files left out); `[]` for a zip it refuses whole (a tour's, one naming an entry twice, one that is no readable zip). Reads only the directory; never rejects. The model import queues one import per model it lists.
- `readZipBundle(zip, zipName, options?, signal?)`: a `ZipBundle`; `options` the `ZipBundleLimits` and `model`, the model to make by its path (the page lists the models first, `listZipModels`, and queues one import each; without `model` the first by path is made):
  - `{ ok: true, kind: "gltf", model, files, skipped }`: `model` the `.gltf`'s path, `files` its text and the entries that text names (its buffers' and pictures' `uri`s, resolved among the zip's parts with one `referenceResolver` as the converter resolves them: a buffer by its path only (`byBasename: false`), a picture by its file name too; a uri named twice is one part), by path; `skipped` the entries used by no model (an entry of a kind no model uses, named on the zip's first model only; and in a zip of one model the parts its text does not name; a part another model of the zip may name is never named);
  - `{ ok: true, kind: "glb", model, glb, skipped }`: a `.glb` inside, taken as it is (the shelf then checks and optimizes it);
  - `{ ok: false, reason }`: in words (`refusal.zipIsTour`, `zipNoModel` (also for a `model` the zip does not hold), `zipNamedTwice`, `zipUnreadable`, `zipTooManyFiles`, `tooLarge`, and for the archive caps `zipTooManyEntries` (`entry-count`) or `zipTooLarge` (every byte cap: the archive, its directory, an entry, the inflation budget)).
    Rejects only when `signal` aborted.
- `zipBundleNotes(bundle, used)`: the notes a model made from a bundle carries: the entries it did not use (`note.unusedFiles`, up to five named).
- `ZipBundleOptions` limits (its `ZipBundleLimits` part, not exported): `maxFiles` (default 1000 entries a model brings along), `maxBytes` (default `ASSET_CEILING_BYTES`, their bytes together), `maxTextBytes` (default `DEFAULT_ARCHIVE_LIMITS.maxTextEntryBytes`, the converter's own text cap: the model's text less its `data:` literals, `dataLiteralBytes` of `gltf-repack.ts`).

## Invariants

- The directory is read through `withZipBlobDirectory` (`zip-blob.ts`, under `withCappedZipEntries` and one `DecompressionBudget` for the archive); macOS metadata (`isMacOsMetadataName`), `.DS_Store`, `Thumbs.db` and `desktop.ini` are skipped. A name the zip carries twice (after those are skipped) refuses the zip (`zipNamedTwice`): which of the two a model names is unclear, so neither is read first-wins.
- A zip holding a `tour.json` (at any depth) is a tour and refused: the start page opens it.
- A zip inside the zip is never opened; it is listed as skipped.
- Several models: with `model`, that one is made; without it, the first by path. No note names the other models: the page queues each as an import of its own, so a note telling the creator to zip each alone (`note.otherModels`, removed) could no longer be reached.
- **One model's parts only:** the model's text is read first (its declared size checked against `maxBytes` before), and only the parts it names are counted, read and inflated, so in a zip of several model folders no model's caps, memory or notes carry another's parts. A text that is no JSON names nothing (the converter refuses it in words). A text past `maxTextBytes` is refused with `refusal.textTooLarge` before it is parsed, as the converter would refuse it; resolving stops with `refusal.zipTooManyFiles(zip, cap)` as soon as the model and the parts named so far pass `maxFiles`, so a text naming thousands of parts costs no more than the cap. A `.glb` is read alone.
- The parts it reads are counted and their declared sizes summed against the caps before any is inflated; each read is capped at what the bundle has left, since a directory can understate a size, and the bytes read are summed against `maxBytes` after each read (a read cap is at least one byte, so the sum, not the read cap, is what holds the bundle's cap exactly). A read stopped by that cap is refused with `tooLarge` against the bundle's own cap (the bytes read before it plus what the entry reached), never in the words of the few bytes it had left.
- A zip past an archive cap (`ArchiveLimitError`) is refused in size words, never as unreadable; anything else that is no readable zip refuses with `zipUnreadable`.

## Tests

`zip-bundle.test.ts`: a folder zip with metadata (only the parts its text names read, an unnamed picture skipped), two model folders in one zip (each model reads only its own parts, under a file cap of three, and its notes are empty), an entry of no model's kind named on the first model only, a `.glb` inside, several models, the model asked for (and one it lacks), a name carried twice, the inflation budget and the entry count in size words (a 64 MiB inflate and a hand-written zip of 20 001 empty entries), `listZipModels` (and none for a zip refused whole), a tour's zip, a nested zip with no model, bytes that are no zip, both caps, abort, the notes, and a property over random entry names (a tour's zip always refused as a tour, each entry claimed once, no metadata kept, only entries of the zip read). `zip-bundle-read-cap.test.ts`: a faked directory whose read stops at the read cap, refused against the bundle's cap (zip.js refuses most understated sizes itself before that cap, so a real zip cannot reach these words in a unit test).
