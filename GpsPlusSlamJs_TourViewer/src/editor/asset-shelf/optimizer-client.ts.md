# optimizer-client.ts

**Purpose:** the page's side of the asset optimizer's module Worker, as an `OptimizerHost`.

## Public API

- `OptimizerWorker`: the part of a `Worker` used (`postMessage`, `terminate`, `onmessage`, `onerror`), so tests can fake it.
- `createOptimizerHost(spawn, page = globalThis.document ?? null, who = "optimizer")`: an `OptimizerHost` over Workers that `spawn` makes; `who` names the Worker in the crash and silence words (the model converter passes `"converter"`); `page` (an `OptimizerPage`: an EventTarget with `visibilityState`) is what the watchdog reads to pause while hidden, null for none. Its `visibilitychange` listener is added when a Worker is spawned and removed when it goes.
- `OptimizerPage`: the part of `document` the watchdog uses, so a test can fake it.
- `OPTIMIZER_SILENCE_MS`: 120 000 (2 minutes), how long a Worker holding runs may send nothing before it counts as crashed.
- `spawnOptimizerWorker()`: the device seam, `new Worker(new URL("./asset-optimizer.worker.ts", import.meta.url), { type: "module" })`; not unit-tested.

## Invariants

- **Lazy:** the Worker is spawned on the first `run`, so a build whose rows need no Worker never starts one.
- **Correlated:** each run gets a fresh job id; answers for an unknown job, or of no known type, are ignored. Progress is forwarded to the run's `control.progress`.
- **Validated:** an answer of a known type is read field by field. A `done` must carry a Blob, an extension the format allows for the run's kind (`tourMediaTypeOf`), and, when given, a width and height that are positive whole numbers; a `kept` or `failed` must carry its words. A model's `model` report is advisory: it is carried through only when its `textures` and `quantize` fields are all finite numbers and its `lod` report reads (finite counts, `skipped` a string or null, `automatic` a boolean, every slider stop of finite numbers), and dropped otherwise (the checked file still lands). A conversion's `conversion` report (`notes` and `used`, both lists of strings) is carried through the same way, and dropped when it does not read. One that does not read rejects its run with words (`the optimizer answered with ...`), so the job fails with Retry instead of hanging or handing a file every later save would refuse.
- **Post:** a `postMessage` that throws (a payload that cannot be copied, a DataCloneError) rejects its run with that error and leaves nothing pending, so the watchdog never kills a healthy Worker for a run it never received.
- **Transfer:** `run`'s optional `transfer` list is posted with the run, so a sound's sample buffers move to the Worker instead of being copied (they are detached on the page afterwards).
- **Abort:** an aborted signal posts `cancel` and rejects the run with an `AbortError`.
- **Crash:** the Worker's `error` event rejects every pending run with `OptimizerCrashed` and terminates it; the next run spawns a fresh Worker.
- **Watchdog:** while the Worker holds runs, any message from it (progress or an answer) restarts a wait of `OPTIMIZER_SILENCE_MS`; a new run starts the wait when none is running but never restarts it, since a new run is no sign that the Worker lives. While the page is hidden the wait is paused (a background tab's timers are throttled or frozen, and one that came due while frozen could fire on resume before the Worker's queued progress is read); showing the page starts it afresh. When it runs out, every pending run rejects with `OptimizerCrashed` (words built from the value and `who`: `the optimizer stopped answering for 2 minutes`) and the Worker is terminated, as for an error event. Chrome does not reliably fire `error` for a Worker killed out of memory, so without it the card stayed "in progress" until the author stopped it. The shelf then tries the job once more like any crash and fails it with those words and Retry. The wait stops once no run is pending. A silence kill, like any crash, rejects every run the Worker held, so every job running beside the silent one is charged an attempt too.
  - **The value:** the longest silent stretch of a healthy run is one step of a primitive's level-of-detail pass: `simplifyModel` reports after the ordering, after the grids and after each pose's measurement (`model-lod.ts.md`, Cost). The model budget, 10 s for the largest measured model (a 57 600-triangle skinned tube), is a desktop figure; a phone takes several times that. Measured on a heavily loaded desktop (about seven times slower than a quiet one): the longest gap between two reports was 4.9 s at 57 600 triangles, 15.0 s at 230 400 and 56.8 s at 921 600 (the whole pass 71.8 s, 106.4 s and 516.7 s). At five times a quiet desktop a phone's gap is then well under 2 minutes up to about 230 000 triangles a primitive; at 921 600 it is about 40 s if the load factor holds, but a phone as slow as that loaded desktop would pass 2 minutes. Not measured on a phone; if a real model's single step proves slower, raise the value or report from inside the ordering.
- **close():** every pending run rejects with an `AbortError`; the Worker is terminated.
- A `spawn` that throws rejects the run with its error.

## Tests

`optimizer-client.test.ts` with a fake Worker (fake timers for the watchdog): lazy spawn, a silent Worker counted as crashed after `OPTIMIZER_SILENCE_MS` while progress keeps it alive and a settled run leaves no watchdog, a new run that does not restart a silent Worker's wait, a run whose `postMessage` throws rejected with no phantom run left, the wait paused while the page is hidden and restarted when shown, correlation and progress, failure words, abort, crash and respawn, close, malformed answers (extension of another kind or none allowed, a zero or fractional size, no Blob, kept or failed without words), a model report carried through, and one that does not read (or whose slider stop does not) dropped; a conversion report carried through and one that does not read dropped; `who` in the crash and silence words.
