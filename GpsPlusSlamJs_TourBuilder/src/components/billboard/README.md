# Component 1 — Clickable billboard

A clickable cylindrical **billboard sprite** that yaws to face the user, plays an
audio clip, and shows an **in-world transport panel** (play/stop button +
seekable progress bar). The warm-up component for the AR audio tour-guide lab —
framework-free and reusable in any Three.js project. Component 8 (AR scene)
reuses these seams directly, swapping desktop pointer picking for the WebXR
`select` ray and the plane sprite for a GLTF model.

## Run it

```bash
pnpm dev            # then open http://localhost:8185/src/components/billboard/
```

Orbit the camera (drag): sprites and the open panel stay upright and face you.
Click a billboard to play it and open its panel; clicking another switches;
the panel button pauses/resumes; the bar fills; tap the bar to seek.

Audio is **spatialized** via `THREE.PositionalAudio` (listener on the camera),
so each clip is panned and attenuated from its billboard's world position — use
headphones and orbit to hear it. The `HTMLAudioElement` still owns transport;
only its output path is spatial, so the pure `core/` logic is untouched.

## Layout

| Path         | What lives here                                                                                                         |
| ------------ | ----------------------------------------------------------------------------------------------------------------------- |
| `demo.ts`    | Standalone demo entry (no AR/GPS/store). Owns the in-memory `TransportState`, `dispatch`, the render loop, and the HUD. |
| `index.html` | The demo's page (loads `demo.ts`).                                                                                      |
| `core/`      | Pure, framework-free, unit-tested logic — the reusable heart. No Three.js/DOM. See `core/README.md`.                    |
| `view/`      | Three.js + DOM view layer that composes `core/` into meshes, audio, and pointer picking. See `view/README.md`.          |

## Data flow

```
pointer / panel tap ─▶ core reducer (transportReducer) ─▶ new TransportState
                                                              │
                                        every billboard.applyState(state)
                                        reconciles audio + panel to match
```

`core/` is the single source of truth: the reducer decides _what_ is true; the
`view/` layer only maps that truth onto `HTMLAudioElement` calls and canvas
pixels, and forwards `tick`/`ended` back in as actions. This one-way flow is
what lets the pure logic be unit-tested with no phone, WebGL, or DOM.

## Assets

Demo fixtures live in `public/billboard/` (`marker-*.png`, `clip-*.wav`),
regenerated by `scripts/make-fixtures.mjs`. They load via
`import.meta.env.BASE_URL` so paths stay deploy-safe. Real tours will resolve
assets by id through the asset-provider interface instead of by path.

## Tests

Pure logic in `core/` is unit-tested (`*.test.ts`, run by `pnpm test:unit`).
The `view/` layer and `demo.ts` composition have no unit tests — glyph
rendering, raycasting, and media playback are view-layer — and are verified
manually via the demo, which stands in for replay e2e (Component 1 has no
movement dependency).
